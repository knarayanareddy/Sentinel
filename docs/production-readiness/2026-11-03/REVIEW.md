# Sentinel — static review

## Scope and verdict

Pinned revision: `1736f0cbec25ed0d3190d692a03bd3c4eadb033e`. Sentinel is a hackathon financial-oversight **prototype**, not an assessed production control. The application-level decision endpoint has no authentication or authorization, and the orchestrator has fail-closed and execution-state gaps. Actual ingress controls, deployment configuration and external side effects are unknown. Runtime, builds, tests, dependency scans and live services were **NOT RUN**.

The snapshot includes the tree and selected samples. Supplemental read-only pinned source requests inspected server, orchestrator, pipeline, nginx and three frontend files. Agent/tool internals, signal implementations, persistence and deployed infrastructure were not comprehensively examined.

## Architecture and product boundary

[Server startup](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/server.py#L20-L50) initializes Vultr vector storage, ingests demo documents, installs the pipeline, registers memo executors and attaches broadcasting. `/api/run` starts scenarios, `/api/decide` resolves frozen actions, and `/ws` streams events and history. React invokes HTTP endpoints and renders the gate. The [pipeline](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/pipeline.py#L38-L47) evaluates drift, probe and citation signals; the orchestrator controls execution. Vultr services and the actual memo sink are external dependencies; sink behavior was not inspected. README safety claims are not demonstrated.

## Findings ledger

- **F01 — high, confirmed static:** [`server.py:134–154`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/server.py#L134-L154) accepts `DecisionRequest`, checks action existence and frozen status, then calls `resolve_frozen(request.action_id, request.approved)` without an identity or authorization dependency. [`orchestrator.py:68–78`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/orchestrator.py#L68-L78) calls the registered executor when approved. A reachable caller who knows a frozen action ID can approve it unless an external control intervenes. Authenticate, authorize the actor and action, and audit decisions; do not assume present exposure or real email delivery.
- **F02 — high, confirmed static:** [`server.py:55–60,70–94`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/server.py#L55-L94) sets `allow_origins=["*"]`, returns demo corpus content, and accepts WebSocket clients before sending history without an application authentication check. `/api/run` also lacks a visible principal ([lines 116–126](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/server.py#L116-L126)). CORS is a browser policy, not authentication, and does not establish WebSocket origin protection. Exposure and sensitivity of streamed data depend on deployment and event payloads. Scope HTTP and WebSocket access independently.
- **F03 — medium, confirmed static / historical CI:** [CI lines 17–19](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/.github/workflows/ci.yml#L17-L19) install requirements and run `python -m compileall -q .`, not tests or frontend checks. The [successful run](https://github.com/knarayanareddy/Sentinel/actions/runs/36902549108) is at the pinned SHA and establishes only that workflow's reported result, not behavioral correctness; reviewers did not run CI or tests. Add behavioral and frontend gates.
- **F04 — medium, confirmed static:** [App.tsx:15–48](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/App.tsx#L15-L48) reports failures through `console.error("Failed to submit decision:", response.statusText)` and corresponding console-only handlers. An operator may not see failure or know whether a decision took effect. Provide visible, announced status and authoritative reconciliation before retry.
- **F05 — high, confirmed static:** [`orchestrator.py:40–55`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/orchestrator.py#L40-L55) calculates `action.is_irreversible and _freeze_policy and _freeze_policy(action)`; when no policy is registered it enters the execution branch. Server startup normally registers the policy ([pipeline:30–36](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/pipeline.py#L30-L36)), so this is conditional on an uninitialized or differently wired path, not proof the normal server bypasses it. Reject or freeze when policy is absent and test the real entry path.
- **F06 — high, confirmed static:** [`orchestrator.py:72–89`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/orchestrator.py#L72-L89) sets `action.status = ActionStatus.RESUMED if approved else ActionStatus.ABORTED` before invoking the executor; exceptions only emit an error before the decision event. The [decision route](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/server.py#L150-L158) seals and returns that status. [GatePage.tsx:92–100](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/pages/GatePage.tsx#L92-L100) displays `✓ Approved — escalation memo dispatched` for an approval even after an executor exception. Actual delivery is unverified, and an effect may have occurred before an exception. Separate approval, execution success and uncertainty; reconcile rather than blindly retry.
- **F07 — medium, confirmed static / unverified operational risk:** [`orchestrator.py:6–35`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/orchestrator.py#L6-L35) declares `_action_registry: dict[str, Action] = {}` and checks it for duplicates. Its process-local lifetime and isolation do not provide durable or cross-worker coordination. Whether another persistence path restores actions was not established. Verify restart and multi-worker behavior before relying on replay protection.
- **F08 — high, confirmed static:** [App.tsx:51–62](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/App.tsx#L51-L62) uses `events.some((e) => e.event_type === "OPERATOR_DECISION")` without matching `action_id`; [GatePage.tsx:54–67,75–89](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/pages/GatePage.tsx#L54-L89) similarly finds any decision and requires `!decisionEvent` to show controls. [useEventStream.ts:27–43](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/hooks/useEventStream.ts#L27-L43) retains prior events when `RUN_STARTED` clears only the frozen action, and accepts replayed history. After decision A then freeze B, A can suppress B's monitor alert and controls; related proposal, citation and incident selection is also unscoped. Scope all displayed evidence and decisions to the current action; browser behavior was not run.
- **F09 — medium, confirmed static:** [OperatorGate.tsx:148–169](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/components/OperatorGate.tsx#L148-L169) calls `onDecision(true)` or `onDecision(false)` without awaiting, then immediately executes `setLoading(false)` in `finally`. The [parent callback](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/frontend/src/App.tsx#L30-L48) is async and catches errors. Pending state therefore does not cover the request, allowing repeat submissions while it is in flight. Await settlement and reconcile ambiguous failures before retry; no duplicate effect was observed.

## Five-discipline assessment

**Correctness:** Policy registration, executor outcome and duplicate handling are separate seams (F05–F07). Test them through the server, including executor calls, not a reimplementation of the policy.

**Automation:** Existing `tests/` and root scripts appear in the inventory; root [`test_duplicate_collection.py:16–26`](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/test_duplicate_collection.py#L16-L26) calls collection initialization and catches exceptions. It is not evidence of an isolated or passing test. Define separate fake-service and approved live tiers.

**Operations:** The checked-in [nginx configuration](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/deploy/nginx.conf#L1-L26) listens on port 80 and proxies API and WebSocket paths without an auth directive. This says nothing definitive about upstream TLS, access restrictions or the deployed file. Startup re-ingestion ([server:26–35](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/sentinel/server.py#L26-L35)) requires provider availability; idempotence and recovery are unverified.

**Security and data:** Authorization gaps are confirmed only at the inspected application boundary. Prompt injection through retrieved documents, secrets in logs or artifacts, package vulnerabilities, vector-store isolation and retention are unverified risks, not confirmed exploits. [Pinned Python requirements](https://github.com/knarayanareddy/Sentinel/blob/1736f0cbec25ed0d3190d692a03bd3c4eadb033e/requirements.txt#L1-L9) are not a transitive integrity or vulnerability assessment. Treat event history and financial documents as potentially sensitive until classified.

**UX/accessibility:** F04, F06, F08 and F09 affect operator status and controls. Keyboard, screen-reader, responsive and reconnect behavior were not tested. Distinguish approval, execution, failure and uncertainty.

## Production blockers, owner decisions and evidence limits

Before real documents or messages, the owner must decide roles, access boundaries, mail sink, hosting/TLS, credentials and data classification. Confirm current deployment, ingress, process count, retention/recovery targets, release authority and domain validation. No certification or vulnerability-free claim is warranted.
